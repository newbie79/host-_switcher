# Host Switcher (Chrome Extension)

hosts 파일을 매번 수동으로 열어 편집하지 않고, 팝업 클릭 한 번으로 도메인을 원하는 서버 IP로
전환해서 테스트할 수 있는 Chrome 확장 프로그램입니다.
여러 개의 도메인을 등록할 수 있고, 도메인마다 여러 개의 서버(IP)를 등록/선택할 수 있습니다.

도메인마다 라우팅 방식을 두 가지 중에서 고를 수 있습니다.

- **리다이렉트**: 확장만으로 동작. 단, HTTPS 도메인은 인증서 경고로 이미지/CSS/JS 같은
  서브리소스가 깨질 수 있습니다.
- **hosts 파일**: 실제 hosts 파일에 항목을 써서 도메인 주소를 그대로 유지한 채 IP만 바꿉니다.
  HTTPS에서도 인증서 문제가 없지만, 로컬에 별도 헬퍼 프로그램을 1회 설치해야 합니다
  (아래 "설치 방법 - 2단계" 참고).

## 설치 방법 (신규 사용자)

처음 쓰는 경우 아래 순서대로 진행하세요. **1단계(확장 로드)만으로도 리다이렉트 방식은 바로
사용 가능**합니다. hosts 파일 방식(HTTPS 서브리소스까지 깨지지 않게 하는 방식)을 쓰려면
2단계까지 추가로 진행하세요.

### 1단계. 확장 프로그램 로드 (필수)

1. 이 압축을 풀어서 폴더로 만듭니다 (예: `host-switcher`).
2. Chrome 주소창에 `chrome://extensions` 입력 후 이동합니다.
3. 우측 상단의 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다** 버튼 클릭 → `host-switcher` 폴더 선택.
5. 확장 아이콘이 툴바에 생깁니다. (고정하려면 퍼즐 아이콘 → 핀 클릭)
6. 확장 카드에 표시된 **ID**(32자리 영문 문자열)를 나중에 쓸 수 있게 메모해둡니다.
   (hosts 파일 방식을 쓸 계획이 없다면 여기서 설치가 끝난 것입니다 — "사용 방법"으로 넘어가세요.)

### 2단계. hosts 파일 방식용 네이티브 헬퍼 설치 (선택)

HTTPS 도메인에서 이미지/CSS/JS까지 깨지지 않게 하려면(hosts 파일 방식), 로컬에 작은 헬퍼
프로그램(`native-host/host_native.exe`, 이미 빌드되어 포함되어 있어 **Python 설치 불필요**)을
한 번 더 설치해야 합니다. 리다이렉트 방식만 쓸 거라면 건너뛰어도 됩니다.

1. **관리자 권한으로 PowerShell**을 열고, 압축을 푼 폴더 안의 `native-host` 폴더로 이동해
   아래처럼 실행합니다 (`ExtensionId`는 1단계 6번에서 메모한 확장 ID).
   ```powershell
   .\install.ps1 -ExtensionId "복사한_확장_ID"
   ```
   이 스크립트는 (1) hosts 파일에 현재 계정의 쓰기 권한을 부여하고(최초 1회만 관리자 권한 필요),
   (2) native messaging host를 레지스트리에 등록합니다.
2. 옵션 페이지(팝업 → "도메인 / 서버 관리")에서 도메인의 방식을 **"hosts 파일"**로 선택하면
   옆에 "네이티브 헬퍼 연결됨" 배지가 뜹니다. 안 뜨면 1번을 다시 확인하세요.

> `host_native.py`를 직접 수정한 경우에만 재빌드가 필요합니다 — "native-host 재빌드하기" 절 참고.

설치를 되돌리려면 같은 폴더의 `uninstall.ps1`을 실행하세요(레지스트리 항목만 제거하며,
hosts 파일 쓰기 권한과 hosts 파일에 남은 항목은 스크립트 안내에 따라 직접 정리해야 합니다).

## 사용 방법

### 1) 도메인 / 서버 등록
1. 확장 아이콘 클릭 → 팝업 하단 **"도메인 / 서버 관리"** 클릭 (옵션 페이지가 열립니다).
2. **"+ 도메인 추가"** 클릭 → 도메인명 입력 (예: `service.example.com`).
3. 해당 도메인 카드 안에서 **"+ 서버 추가"** 로 WEB1, WEB2, WEB3, WEB4 등 원하는 만큼
   이름 + IP를 등록합니다.
4. 여러 도메인을 같은 방식으로 계속 추가할 수 있습니다.
5. **저장** 클릭.

### 2) 서버 전환
1. 확장 아이콘 클릭.
2. 등록된 도메인별로 서버 목록(라디오 버튼)이 표시됩니다.
3. 원하는 서버를 클릭하면 그 도메인만 즉시 해당 IP로 라우팅됩니다. (다른 도메인 설정에는 영향 없음)
4. **IP 미선택**을 선택하면 그 도메인은 원래 DNS(hosts 파일 없는 상태)로 되돌아갑니다.
   도메인을 새로 등록하면 기본값이 바로 이 상태입니다.
5. 브라우저 재시작 불필요, 새로고침(F5) 또는 새 요청부터 바로 반영됩니다.

## 동작 원리

### 리다이렉트 방식
- Chrome의 `declarativeNetRequest` API로, 등록된 도메인 중 "IP 미선택"이 아닌 도메인의 요청을
  선택된 서버 IP로 리다이렉트합니다.
- 리다이렉트 후에도 서버가 정상적으로 vhost 라우팅을 하도록 `Host` 요청 헤더는 원래
  도메인명으로 유지시킵니다.
- 도메인마다 고유한 규칙 ID(`ruleId`)를 부여해 여러 도메인의 라우팅 규칙이 서로
  충돌하지 않습니다. 이 ID는 도메인을 삭제해도 재사용되지 않습니다(계속 증가).

### hosts 파일 방식
- 확장이 로컬에 설치된 네이티브 헬퍼 프로그램(`native-host/host_native.exe`, PyInstaller로
  빌드된 단일 실행 파일)에 메시지를 보내, 실제 `C:\Windows\System32\drivers\etc\hosts` 파일에
  `IP 도메인` 항목을 씁니다.
- URL 자체는 바뀌지 않고 DNS 해석만 바뀌는 것이므로, HTTPS여도 인증서 경고 없이
  이미지/CSS/JS까지 정상적으로 로드됩니다.
- **Chrome 자체 DNS 캐시 주의**: hosts 파일이 바뀌어도 Chrome이 최근에 조회한 도메인은
  자체 캐시(대략 1분)를 잠깐 더 씁니다(새 탭이어도 마찬가지 — 캐시는 탭이 아니라 브라우저
  전체가 공유). 그래서 팝업에서 다른 서버로 전환하면 `chrome://net-internals/#dns` 탭이
  자동으로 열립니다 — 거기서 **"Clear host cache"** 를 눌러야 확실하게 새 IP로 붙습니다.

## HTTPS 관련 주의사항 (리다이렉트 방식)

- HTTPS 서비스는 도메인 기준으로 인증서가 발급되어 있기 때문에, IP로 직접 연결하면
  브라우저가 `NET::ERR_CERT_COMMON_NAME_INVALID` 등 인증서 경고를 표시할 수 있습니다.
- 사내 테스트 용도로 인증서 오류를 무시해도 된다면, 경고 화면에서
  **"고급" → "(안전하지 않음) 계속 진행"** 을 클릭하면 메인 페이지는 접속됩니다. 다만
  이미지/CSS/JS 같은 서브리소스는 브라우저가 클릭스루를 제공하지 않아 계속 깨질 수 있습니다.
- 이 문제를 완전히 없애려면 해당 도메인을 옵션 페이지에서 **hosts 파일 방식**으로 바꾸세요
  (위 "설치 방법 - 2단계" 참고).

**주의**: hosts 파일 방식은 PC 전역(OS 레벨) 설정이라, 리다이렉트 방식과 달리 Chrome
프로필별로 다른 서버를 보게 하는 기능이 적용되지 않습니다. 그 PC에서 마지막에 저장한
매핑이 시스템 전체에 적용됩니다.

## 참고

- 설정(도메인/서버 목록)은 `chrome.storage.sync`에 저장되어 같은 Google 계정으로
  로그인한 다른 PC의 Chrome과도 동기화됩니다.
- 현재 선택 상태(어떤 도메인이 어떤 서버로 라우팅 중인지)는 `chrome.storage.local`에
  저장되어 PC(프로필)별로 독립적으로 유지됩니다.

## native-host 재빌드하기 (유지보수용)

`native-host/host_native.py`를 직접 수정했을 때만 필요합니다. 평소 사용자는 이 절을
몰라도 됩니다(이미 빌드된 `host_native.exe`가 리포에 포함되어 있음).

1. PC에 Python과 PyInstaller가 필요합니다: `pip install pyinstaller`
2. `native-host` 폴더에서 아래 명령 실행:
   ```powershell
   pyinstaller --onefile --noconsole --name host_native --distpath . --workpath build --specpath build host_native.py
   ```
3. `native-host/host_native.exe`가 새로 생성됩니다. `build/` 폴더는 중간 산출물이라
   지워도 됩니다.
4. 이미 `install.ps1`을 실행해 등록해둔 상태라면 재설치는 필요 없습니다 — 레지스트리는
   `host_manifest.json` 파일 경로만 가리키고, 그 파일의 `path`는 이미 `host_native.exe`를
   가리키고 있어서 새로 빌드된 exe가 바로 다음 호출부터 사용됩니다.
